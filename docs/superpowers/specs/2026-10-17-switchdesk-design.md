# 双栖 SwitchDesk：Mac / Windows 共用显示器设计

日期：2026-10-17  
状态：用户在 V0.4 调整后回复“继续”，进入实施阶段；技术能力与体验目标仍须实机验证。  
当前交付：交互原型 V0.4、诊断工具、Windows 0.1.0 切屏版，以及 Mac/Windows 0.2.0 桌面联动版。用户已确认 Windows 0.1.0 能切屏。0.2.0 接入真实系统输入、剪贴板和屏幕捕获，仅在配对、开关和系统授权条件满足时工作；构建与自动化验证不能替代双机原生验收，详见桌面版验证记录。

A2a 的历史 Windows 45 秒观察报告中，18 次读取均为 17；用户当时仅运行脚本，不能据此确认非当前输入回读能力。随后用户确认安装版能够切换，属于新增切屏证据，不扩展为所有接线和共享功能均已验证。观察工具不增加产品检测页面。

## 1. 使用体验与范围

Mac 与 Windows 分别连接 AOC 27G2，并保持开机。按一次可配置的快捷键，显示器输入与键鼠控制目标一起切到另一台；再按一次切回。主画面沿视频线直达显示器。

已确认的需求：

- HDMI 直连、USB-C 转 HDMI、USB-C 转 DP 三种接法均纳入适配与验收，不以当前个人接法限制产品。
- Windows 接有线网络、Mac 接 Wi-Fi 可以组合使用，条件是两端局域网可达。发现失败时支持手动输入地址配对。
- 键鼠来源可选 Windows 的 USB 接收器键鼠，或 MacBook 内置键盘与触控板。来源和控制目标独立；切屏不改变来源。
- 双向复制粘贴支持文字、图片、文件、文件夹，不依赖当时使用哪台的键鼠。
- 控制台右侧预览另一台电脑：当前 Mac 时看 Windows，当前 Windows 时看 Mac。预览可暂停、放大和关闭。
- 连接识别与健康检查默认在后台完成；不设置“设备与连接”独立页面，正常情况不展示检查过程。
- 用户最新明确要求：正常切换从按键到目标画面和键鼠可用均不超过 1 秒。超过 1 秒即未达标；不能用命令发送或 DDC 回读耗时替代实际黑屏时间。目前未有满足该要求的实机证据。

首版以两台电脑、一台共享显示器为范围，允许 Mac 自带屏幕继续存在。拟定构建基线为 Apple Silicon + macOS 13 及以上、Windows 10 22H2 / Windows 11 x64；用户 Windows 的实际版本由安装诊断读取并验证。Intel Mac、Windows ARM、多台主机、互联网远控、预览内交互、音频路由和系统多指手势扩展不属于首版。触控板首版支持移动、点击、拖动、右键和双指滚动。

## 2. 路线选择

| 路线 | 对使用体验的影响 | 决策 |
| --- | --- | --- |
| 显示器切输入 + 局域网共享 | 主画面保留原生视频路径；切换速度和控制能力依赖显示器与转接链路 | 推荐作为本项目主路线 |
| 局域网远程桌面 | 可避开显示器切源，但主画面依赖网络、编码与解码 | 保留为用户另行选择的替代路线，不自动降级过去 |
| 外置硬件 KVM | 设备处理视频与 USB 切换；需另购设备，Mac 内置键盘/触控板和共享剪贴板仍需软件 | 首版不要求额外购买 |

27G2 有 HDMI 与 DP 视频输入。能够显示画面，不等于该线材、转接器和主机组合能够传递 DDC/CI 控制指令。软件应检测实际能力，不能仅凭型号或连接器名称显示“兼容”。

兼容结果分别保存：显示器识别、输入映射、可发命令的主机/链路、两个切换方向、回读方式、切换耗时、未选中输入时的桌面捕获可用性。显示器或链路改变后重新校准。只验证一个方向，不可显示“双向通过”。

## 3. 界面与首次使用

延续浅色、紫色主操作按钮的 V0.4 原型。三个入口：

| 页面 | 用户能做什么 |
| --- | --- |
| 控制台 | 查看当前控制目标、切换电脑、预览另一台、选择键鼠来源、查看当前传输 |
| 剪贴板与文件 | 开关共享、查看当前内容类别、查看传输进度、取消或重试 |
| 设置 | 修改快捷键、调整来源键盘映射、开关预览和登录启动；需要时展开“连接详情与排查” |

首次流程：两端安装 → 后台发现 → 必要时用简短弹窗添加设备并核对配对码 → 按功能申请系统权限 → 后台识别显示器与输入映射 → 仅在不能自动确定或需要首次切源验证时提示 → 进入控制台，选择键鼠来源。已有配对和已验证映射自动复用，不重复展示向导。

后台默认做设备发现、权限状态、链路识别与无副作用的健康检查。正常情况不弹窗、不展示检查步骤、不要求点击“检测”；控制台仅保留设备在线状态。后台检查不得擅自切屏或制造黑屏。需要主动双向切源验证时，在首次使用或用户实际发起切换时给出一次简短引导，并说明恢复方法。

只有需要用户处理的授权、配对、映射歧义或连接异常才提示。连接异常显示一条简短说明与“查看原因”；点击进入设置并展开“连接详情与排查”。详情默认折叠，包含当前接口、错误原因和手动重试。连接恢复后移除异常提示，不弹成功窗口。原型中的异常模拟按钮放在应用窗口之外的折叠审阅工具中，不属于正式产品。

不要求用户认识 DDC/CI。错误提示用“暂时无法自动切屏”“切换未确认”等语言，按问题提供显示器设置、线材或手动切源的具体恢复方式。

预览里的设备、成功状态与文件都是示例，正式产品的空状态必须从“尚未配对/尚未检测”开始。不能把示例成功状态移植为产品默认值。

## 4. 组件与职责

建议采用 Tauri 2 + React/TypeScript 构建共享界面，Rust 实现会话状态和网络核心，macOS/Windows 使用各自原生适配层。界面关闭后进程继续驻留菜单栏或托盘；只有显式退出才停止共享。界面调用受限命令接口，不直接捕获系统输入或访问远端文件。

| 组件 | 输入与输出 | 职责 / 依赖 |
| --- | --- | --- |
| 配对与会话 | 发现信息、配对确认 → 已认证会话 | 局域网发现、设备身份、连接与重连 |
| 切换协调器 | 切换请求 → 阶段事件、成功或失败 | 串行协调显示器与键鼠；依赖显示器、输入和会话适配器 |
| 显示器适配器 | 发现/读取/切源请求 → 能力与结果 | Windows 使用物理显示器 API；Mac 使用经验证的 Apple Silicon DDC 适配，不把某个工具的适配范围当作整机保证 |
| 输入适配器 | 来源事件 → 本地放行或远端事件 | 捕获、屏蔽、注入、释放按键；紧急热键优先 |
| 剪贴板适配器 | OS 剪贴板变化 ↔ 带版本的内容提议 | 文本/图片格式转换、防止回环、原生文件粘贴衔接 |
| 文件传输 | 显式粘贴请求、文件清单 → 进度/完成 | 流式传输、校验、取消、重试；不删除来源文件 |
| 预览适配器 | 可见窗口订阅 → 带时间戳的帧 | 原生屏幕捕获、缩放、限帧；不保存视频 |
| 诊断记录 | 状态与错误码 → 本地报告 | 耗时、链路、错误；不记录按键正文或剪贴板内容 |

同一配对会话中控制消息、输入事件、文件流与预览帧分队列处理；大文件和预览不得阻塞释放按键、切换及心跳。连接使用成熟 TLS 实现与已配对设备身份校验，不自创加密。新设备必须在两端确认，撤销配对立即断开。

键鼠来源设备持有控制协调权；另一端的切换按钮也向其提出请求。变更来源必须先停止旧来源转发并释放按键，再确认新来源就绪，最后更新双方状态。确认失败保留原来源；连接丢失时两端解除远程输入并恢复各自本地输入，防止双方同时截获。

## 5. 切屏、输入与恢复

默认切换热键：Ctrl + Alt/Option + Space，可录制修改；冲突时提示。默认紧急收回：Ctrl + Alt/Option + Esc，在来源电脑本地拦截，恢复来源电脑的键鼠。它不保证显示器随之切回，UI 必须明确提示物理输入选择方法。

一次切换采用有请求编号的串行流程：

1. 检查目标在线、输入权限、显示器映射及已验证切源路线；拒绝条件不满足的请求。
2. 释放旧目标所有受控按键/鼠标按钮，暂不转发普通输入。切换组合键不发送到目标应用。
3. 通过校准后可用的控制链路发送切源指令。执行命令的电脑不必等于键鼠来源；必须验证切过去后仍有切回路线。
4. 等待显示器输入回读及目标输入就绪确认。DDC 写命令成功只代表命令返回，不能单独代表屏幕已点亮。
5. 若该链路能够确认输入已切换，则在已校准的画面稳定时间后更新目标并恢复输入，预览订阅改为另一台。
6. 若只能确认命令发送、不能确认输入，在校准中标为“无法可靠确认”。首版不把它纳入全自动成功路径，提供用户手动确认的引导模式。

软件不能完全测量液晶画面是否已亮，因此真实黑屏时间仍需用户观察或外部计时验证；诊断同时保留命令完成时间与用户确认时间，避免混为一谈。上述 1 秒验收使用用户可见画面及输入均恢复的时间。首次安全试切的 10 秒自动返回计时不是正常切换延迟；若试切期间始终黑屏，只恢复了原桌面，不视为目标画面验证成功。

超时预算建议 5 秒，超过即终止此次切换。自动尝试恢复原输入至多一次；恢复是否成功也需证据。无法确认时保留“显示器状态待确认”，释放远端按键、恢复来源电脑本地输入、提示显示器按键切源。失去心跳或进程退出同样释放受控输入；目标端设置输入租约，来源崩溃后也能解除按键。

切换期间忽略重复请求，不排队累积。错误、超时和重连携带会话/请求版本，迟到确认不能覆盖新状态。重新连接先对齐双方状态，不静默恢复远程控制。

输入默认透传物理键位；另提供常用编辑快捷键映射，限定复制/粘贴/剪切/撤销/全选的 Ctrl 与 Command 转换，避免全局替换 Ctrl 影响其他组合键。UAC 安全桌面、登录前桌面、系统保护输入与部分提权应用按平台限制提示不可控，不承诺绕过系统保护。

## 6. 双向剪贴板与文件

文字和图片在复制后同步；文件/文件夹先同步清单与可用性信息，在目标文件管理器请求粘贴时传输内容。每条内容有来源设备、会话和版本；写入远端剪贴板时标记，避免再次广播回来源。两端同时复制按会话内顺序裁决，过期版本不覆盖新版本。

原生文件复制是独立难点：Windows 的文件路径列表不能直接给 Mac 使用，必须由目标平台提供本地可消费的数据对象。Windows 评估虚拟文件描述与流式内容提供；Mac 评估原生剪贴板延迟提供及 Finder 兼容路径。第一阶段先做 Finder ↔ Explorer 单文件、目录与菜单粘贴的可行性实验，不能仅拦截快捷键假装实现原生粘贴。

文件/文件夹需求保持在首版范围；若 Finder 或 Explorer 无法可靠完成延迟粘贴，该阶段判为不通过，提交具体限制和替代交互供用户决定，不能静默换成“去应用里下载”。

传输规则：

- 只处理用户复制产生的清单；远端不能任意读取来源路径。收到的相对路径必须限制在目标目录内。
- 首版只复制，不执行跨机剪切删除。文件名不合法、大小写冲突、符号链接或特殊文件给出明确提示，不静默改内容或递归跟随链接。
- 大文件流式读写，临时文件完成并校验后再交付；不把整个文件读入内存。取消/失败保留清晰结果，部分内容不能显示“成功”。
- 同名冲突提供保留两份、替换、跳过；优先使用目标文件管理器的原生冲突交互，必要时由应用接管。
- 来源文件在传输期间改变则失败并提示重新复制。首版重试重新传输未完成文件，不承诺断点续传。
- 复制新的内容不取消已经开始的粘贴任务；任务固定使用自己的版本。关闭共享取消进行中的共享传输并撤销由本应用提供的待取内容，不清除用户随后写入的本地剪贴板。
- 默认不保存剪贴板历史。文件清单失效、空间不足、权限不足和来源离线均有可操作提示。

## 7. 另一台电脑的实时预览

首次打开向另一台订阅其桌面，采集需要系统授权。目标为 640 × 360、5 帧/秒，只读显示；放大仍为只读。Mac 使用 ScreenCaptureKit，Windows 使用原生屏幕捕获接口。实际桌面流在本机缩放/编码，通过已认证局域网连接发送；过期帧直接丢弃，不排队造成长延迟。

控制台或放大预览可见时才订阅；两者都不可见、暂停、关闭、锁屏或断线时停止采集和发送。不录音、不落盘录屏。超过 2 秒没有新帧时显示“画面已停止更新”，停止使用实时标记；锁屏、权限缺失或显示器消失时遮盖旧帧并显示原因。

切走显示器输入后，另一台是否仍保留可捕获的桌面必须实测。Mac 优先捕获该共享外接显示器；如只能使用内置屏幕，标明“MacBook 内置屏幕”，不静默冒充共享显示器画面。Windows 若没有可捕获屏幕则显示不可用。虚拟显示驱动不默认安装；是否引入由实机结果决定，必要时提出单独方案。

## 8. 验收与开发顺序

先验证影响总体可行性的原生能力，再做完整产品。模拟器通过和 UI 演示不能替代硬件验收。实施计划按阶段拆开，首先编写阶段 A 的详细计划；后续阶段依据实测能力单独细化，避免一次把所有子系统都按未经验证的假设实现。

| 阶段 | 产物 | 通过条件 |
| --- | --- | --- |
| A：能力实验 | 两端诊断与最小验证程序 | 27G2 双向切源；输入接管/释放；Finder ↔ Explorer 原生文件粘贴；非当前输入桌面捕获分别有可复现结果 |
| B：最小可用闭环 | 两端配对、控制台、热键、输入来源选择、恢复 | 两种来源各能双向切换；断网、退出、连续热键均不遗留按下状态 |
| C：内容共享 | 文本/图片、文件与文件夹、预览、进度和失败页 | 双向内容正确；文件传输时键鼠保持可用；隐藏页面后停止预览采集 |
| D：安装与验收 | Mac 应用、Windows 安装包、诊断报告 | 两端实际安装运行；三类 Mac 视频接法有实测矩阵；未覆盖组合明确标记未验证 |

拟定验收样例：

- 在每个已验证连接组合、每种输入来源上各做 10 次往返；记录实际画面恢复时间、输入恢复时间和失败次数。目标每次均在 1 秒内，超出则标为未达到体验目标并分析原因。
- Mac/Windows 两种来源验证移动、左右键、拖动、滚动、中英文输入和编辑快捷键；长按按键过程中断开连接，目标须释放按键。
- 两端文本含中文/换行，图片含透明度；文件含空文件、中文名称、1 GB 文件和多层目录。目标文件内容逐个校验；验证同名冲突、磁盘不足、来源更改、取消与重试。
- 原生粘贴验证键盘快捷键、菜单及右键粘贴，不能仅覆盖应用内按钮。
- 预览验证切换前后对象正确、锁屏遮盖、权限撤销、断网、无显示器、窗口隐藏、暂停恢复；不发送隐藏期间帧。
- 纯逻辑测试覆盖切换状态机、迟到确认、输入租约、剪贴板去重、路径越界与传输取消。端到端测试使用真实平台适配器；Mac 上的编译或模拟测试不算 Windows 验收。

第一阶段若发现无法切回、无法安全释放输入或文件粘贴不可行，则停止扩展该能力，保留诊断结果，提出具体调整。可以并行继续不依赖该问题的已授权设计工作，但不报告整体完成。
