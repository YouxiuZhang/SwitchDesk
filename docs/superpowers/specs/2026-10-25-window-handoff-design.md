# Mac 扩展屏窗口收回

用户已选择保留两个独立桌面，在切到 Windows 时将 Mac 窗口收回笔记本屏幕。该选择是本变更的功能授权；沿用当前项目，不重复询问同一方案。

## 行为

- 不改变显示器扩展/镜像配置，不修改分辨率、主屏和视频接口映射。
- 仅在已配对连接给出确定目标 Windows、且切屏不在进行中时，把共享外屏上的普通 Mac 窗口移到内置屏可用区域。
- 仅一块外屏和一块在线内屏时自动识别；无内屏、镜像、多外屏等不明确情况跳过，避免移动错误屏幕上的窗口。
- 内屏已有窗口不动；保留窗口大小，超出内屏可用区域时仅缩小到能放下的尺寸。新打开或从最小化恢复到外屏的窗口也收回。
- 切回 Mac，窗口仍在程序收回后的位置且原外屏在线时，恢复其原位置和大小；用户手动改过的位置/大小保留。等待外屏重新上线最多 15 秒。
- 全屏、最小化、隐藏应用、不能修改位置的窗口跳过，不强退全屏、不切换 Spaces。说明中明确这个限制。
- 断线、未知目标、切屏中、权限失效时停止迁移动作；已收回的窗口留在可见内屏，不擅自放回不可见外屏。
- 所有 AX 窗口消息在独立串行队列执行，设置短超时，不阻塞键鼠或切屏链路。快速反复切换通过操作代数取消旧任务；轮询不堆积。
- 窗口记录只存内存，不读取标题、文档内容，不发送给 Windows，不保存到磁盘。

## 接入

新增纯布局/记录策略与 AppKit/Accessibility 适配器。NativeCoordinator 把连接和权威显示目标传给适配器；关闭应用时停止扫描。设置页提供默认开启的“切到 Windows 时收回 Mac 窗口”开关及执行状态。

仅升级 Mac 到 0.2.11，协议保持 desktop-v1，Windows 0.2.10 不变。构建隔离包；不覆盖当前已授权运行实例，避免临时签名再次使当前权限失效。

## 验证

纯 Swift 测试覆盖坐标变换、外屏主屏/负坐标排列、窗口缩放与边界、只处理外屏、保留手动布局、外屏缺失/多外屏、重复状态、过期任务以及断线取消。原有 UI review 隔离测试与产品回归继续通过；构建、签名和 ZIP 内容验证通过后交付。真实跨应用窗口迁移需要安装新版并授权后的实机验证，不能用模拟测试冒充。
