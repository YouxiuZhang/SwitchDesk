# Windows 鼠标控制 Mac 的延迟反馈

2026-10-25 用户确认：Windows 上的鼠标控制 Mac 时跟手有延迟，偶尔卡顿；不是仅移动速度偏慢。

## 当前实机状态

通过正在运行的 Mac 双栖设置页读取：Mac 0.2.8、Windows 0.2.8.0，设备已连接；辅助功能、输入监听已授权，事件钩子已安装并启用。控制台显示正在控制 MacBook，Windows 键鼠来源已启用。

当前 Windows 进程尚未使用 0.2.9 修复。此前回归证明 0.2.8 控制队列积压超过阈值时会丢弃相对鼠标位移，0.2.9 改为保留总位移的相邻合并，并将帧头和正文合为一次发送。详见 `desktop-0.2.9-verification.md`。本次不能把用户全部延迟都归因于该问题，先部署已有修复再实测。

已核验 `dist/product/SwitchDesk-Windows-0.2.9.exe` SHA-256 与交付记录一致：`1b69d166cc6d5feaadb81efbb306280489a276d252593e64b0f08afe495f332e`。本次未替换 Mac 应用，未修改系统权限或鼠标速度。

对已配对地址进行 15 次 ICMP 探测，没有收到响应。应用当时仍显示已连接；ICMP 不响应不足以证明真实控制连接丢包，也无法据此计算往返延迟。

## 后续验证

Windows 托盘彻底退出旧进程后安装并启动 0.2.9；Mac 设置页应显示 Windows 0.2.9.0。然后复测 Windows 鼠标控制 Mac 的跟手与卡顿。

若新版仍有延迟，继续测量端到端输入处理。代码检查发现 Mac 控制回调仍经过主队列、注入逐条排队；这是待测的积压位置，本次没有证据证明它是本次症状的根因，未据此继续叠加修改。
