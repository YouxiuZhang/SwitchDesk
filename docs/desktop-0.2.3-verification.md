# Windows 0.2.3：画面确认修复

用户明确表示已看到 Mac 画面，但“我看到 Mac 画面，并已切回 Windows”无法勾选。

确认的代码原因：0.2.2 界面只有在自动试切记录 `TrialReturned` 为真时才允许勾选，`ConfirmSeen()` 也有同样前提。自动结果缺失、被会话变化丢弃或无法回读时，用户已观察到的画面没有确认入口。无法从本机证据确定用户当时具体落在哪一种自动失败分支。

0.2.3 的处理：

- 选定有效显示器与不同的 Mac 输入口后，可主动勾选；点击只调用显示器读取 worker，不调用切屏写入。
- 当前输入回读等于所选 Windows 输入才接受用户的画面确认、保存映射并启用切屏。
- 核对过程锁住显示器操作；确认结果绑定独立的映射版本，不因局域网重连丢弃，也不能用旧读取结果确认新选择。
- 读取失败、输入不符或未结束的显示器操作给出可见原因；不伪造 DDC 写入成功。
- Mac 继续使用 0.2.2，协议未改变。

验证：真实 `Coordinator.cs` / `SwitchState.cs` 编译执行，替换原生读取、输入、传输边界。新增测试修复前 2 项失败，修复后 5 项通过；覆盖 8 种确认情形。原有切屏回归 5 项、产品规则 2 项通过，共 12 项。Windows C#5 / .NET Framework 4.8 x64 全量交叉编译通过。

未在此 Mac 上执行 Windows 原生界面或实体显示器切换，不能据此宣称黑屏时长达到 1 秒。

交付：`dist/product/SwitchDesk-Windows-0.2.3.exe`。完整性校验、安装载荷比对另见本次工具输出。未提交或推送代码。
