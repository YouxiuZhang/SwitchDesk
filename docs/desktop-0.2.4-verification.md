# 双栖 0.2.4：保留回到 Windows 的路径

用户提供截图：Mac 已连接、Windows 预览实时，但全局目标“尚未确认”，“恢复 Windows 画面”禁用；用户报告切到 Mac 后切不回 Windows。

代码中确认的故障路径：

1. 切向 Mac 的写入可能已生效，但随后回读失败。旧代码将目标标为未知、撤销确认，同时把回 Windows 也禁用。
2. 三秒预期窗口之外的显示器通知会直接清空接口记录，丢失已确认的 Windows 回切地址。
3. 输入权限丢失或会话变化修改 epoch。旧代码丢弃正在执行的显示器操作结果，可能留下 switching=true，或在已经切到 Mac 时仍显示 Windows。

截图不能唯一确定本次落在哪个分支，也不能证明显示器切源后仍提供可用的 Windows DDC 通道。

修复：

- 用户确认或验证保存配置后保留独立的恢复映射。回读不确定或显示器通知只撤销普通控制，不清除恢复地址；用户主动改选、刷新、撤销确认才清除旧地址。
- 新增 `can_recover_windows` / `restore_windows_request`。Mac 提供独立入口；旧 Mac 在未知目标时的普通按钮也可以请求恢复 Windows。
- 恢复仅写之前确认的 Windows 输入口，沿用 worker 的身份、输入读取、进程隔离及写入封锁。失败仍明确报告未知，不启用远端输入。恢复能力不授权再次切往 Mac。
- 物理显示器结果通过操作编号及映射版本关联。权限/网络变化只解除输入控制，不丢弃有效物理结果或留下切换状态。
- 重启时读到保存显示器的 Windows 或 Mac 任一接口都能恢复配置。身份由 MainForm 对保存的 ID/name 做精确比对，未知接口不能恢复。

验证：

- `test_display_recovery.py` 编译执行真实 Coordinator/SwitchState，仅替换设备/网络边界。最初 8 项测试中 5 项失败；修复后扩展为 11 项，覆盖 15 种情形：正常往返、回读失败、延迟显示事件、权限失效、断线、重连、恢复失败重试、worker 未退出、用户改选、未确认设备、显式恢复消息、禁止恢复能力再次切往 Mac、在 Mac 画面重启、未知输入拒绝。
- 原有切屏 5 项、画面确认 5 项、产品规则 2 项一同验证。
- Mac arm64/macOS 13 全量编译及临时签名校验；Windows C#5/.NET Framework 4.8 x64 全量交叉编译。安装包 ZIP/NSIS 完整性及 Windows 载荷比对。

未执行 Windows 原生界面或物理显示器双机联调。若 Windows 在非活动输入上无法枚举/读取显示器，恢复仍会失败，需要用显示器信号源菜单恢复；本次没有绕过这个硬件边界，也未验证一秒切换。
