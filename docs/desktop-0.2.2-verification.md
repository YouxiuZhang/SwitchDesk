# 双栖 0.2.2 回归修复

用户报告：旧 0.1.0 实验包能切屏；0.2.0 显示已连接但有已断开文字、切屏按钮禁用，另有试切黑屏后回退反馈。用户后来明确描述旧包可用，应优先修新版软件回归，不以 Mac 某一时刻仅显示内建屏推断接线故障。

## 确认并修复的问题

- 0.2.0 的 `Coordinator.CanRequestSwitch` 和 `SwitchAsync` 错误地把视频切换绑定到网络连接及两端键鼠能力；Mac 界面又使用输入 `ready` 控制切屏按钮。旧程序直接调用相同的显示器适配器，没有这些条件。
- 0.2.2 以 `can_switch` 单独表示视频切换能力；Windows 可独立切屏，Mac 按钮需认证连接。映射确认、在途操作、回读和恢复保护仍保留。
- 输入 `ready` / `armed` 独立检查连接及输入权限。缺权限的纯视频切换不激活输入，之后授权也不会自动激活；用户再次选择来源或正常切换才启用。
- 重连时重新计算状态提示，不保留已断开文字；缺权限或未确认映射显示具体操作。
- 预览关闭与 Windows 锁屏分别提示。Mac 返回应用时重新检查已授予的权限，不自动弹授权或代用户批准。

## 验证

`tests/product/test_coordinator_switch.py` 编译真实 `Coordinator.cs` 和 `SwitchState.cs`，仅将网络、原生输入和显示器写入替换为测试边界，确认实际命令是否被发出及是否仍禁用未授权输入。

- 修复前：5 项中 3 项失败，复现缺权限/未连接时不发出命令。
- 修复后：5/5 通过，覆盖缺权限仍切视频、未联网仍切视频、未确认映射不写、授权输入仍可用、回读失败撤销控制。
- 原有 Windows 产品规则 2/2 通过。
- Mac arm64 / macOS 13 全量编译与签名校验通过；Windows C#5 / net48 x64 全量交叉编译通过。

这些检查不是 Windows 真机或 HDMI 画面实测。切源 worker 与旧实验包仅命名空间/主窗口互斥差异，底层 `MonitorControl.cs` 未改。本修复不能直接证明“试切期间黑屏”已消失，也未证明 ≤1 秒体验达标。
