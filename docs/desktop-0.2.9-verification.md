# Windows 0.2.9：切屏后键鼠继续跟随

## 现场证据

Mac 0.2.8、Windows 0.2.8.0 已连接，辅助功能与输入监听均已授权，事件钩子已安装启用。先在 Windows 画面下选择 Windows 键鼠来源，应用显示已启用；点击“切换到 Mac”，即时回读耗时约 721ms、三次读取仍未确认，稍后的读取把目标更新到 Mac，却把键鼠共享改回待启用。

再次选择 Windows 来源后，用户明确确认 Windows 鼠标可以控制 Mac，但不够流畅。该证据区分了输入通路和切屏后停用状态两个问题。

## 修复

Coordinator 为正常切换保留该次操作的输入授权快照（epoch、连接代次、来源）。切屏回读未确认时仍停止输入；后续只读核对目的接口成功，且快照与当前状态一致、两端权限与连接仍有效时，继续原来源。期间发生断线、重连、权限失效、其他输入操作或映射变更，就不沿用旧授权。显式恢复 Windows 不生成快照，仍不自动启用键鼠。

Windows 控制消息队列原先在积压超过 32 条时直接丢弃鼠标相对移动，新版改为合并尾部同 epoch 的相邻移动，累计任一轴超出 ±2048 时另起帧，不跨越按键、点击、释放、滚轮、快捷键或心跳。保留 512 条容量、严重拥塞断开、断线清空与本地输入恢复。网络帧长度头和 JSON 正文合为一次 Write，协议格式不变。

## 已完成的验证

- 新测试先复现 Windows 来源往返、Mac 来源返回 Windows 后无法继续输入的两项失败；修复后 4 项回归通过，涵盖待确认暂停、往返保留来源及权限/会话变化后的停用。
- 传输回归先复现旧代码 5 项失败，修复后 8 项通过。队列积压模拟中，10,000 个 `(3,-2)` 移动原先只保留 `(99,-66)`，修复后合为 15 帧，完整保留 `(30000,-20000)`。另测并发 30,000 条移动、事件顺序屏障、epoch、边界、在途对象不可变、完成唤醒和饱和断开。
- 完整产品回归：`python3 -m unittest discover -s tests/product -p 'test_*.py' -q`，67 项通过，耗时 32.732 秒。包括 TLS、本地回环会话、文件协议、恢复、切屏状态和输入传输。
- Windows .NET Framework 4.8 / C#5 交叉编译通过，程序集版本核对为 `0.2.9.0`。NSIS 安装包 `dist/product/SwitchDesk-Windows-0.2.9.exe` 构建成功，7-Zip 完整性检查通过；解包后的 EXE 与中文说明均逐字节匹配构建产物。
- `dist/product/SHA256SUMS-0.2.9.txt` 记录本次 Windows 安装包及沿用的 Mac 0.2.8 ZIP 校验值。没有替换正在运行的 Mac 应用或修改系统权限。

Mac 继续使用已授权的 0.2.8，本次不重签、不重装 Mac 应用。实际新包的流畅度及切屏后键鼠跟随仍需用户在 Windows 安装后验收；不以单元测试代替双机实测。
