# 双栖 0.2.6：回读与键鼠就绪

## 实际证据

- 用户确认：黑屏来自控制台切换按钮/快捷键，不是安全试切。该正常路径没有试切的固定 10 秒等待。
- 本机界面只读检查：Mac 0.2.5、Windows 0.2.5.0，连接正常；最近一次切屏报告“写入后回读失败”，目标未知；Mac 键鼠能力未就绪。不能据此推断黑屏全由程序或显示器造成。

## 修复

- 一次 DDC 写入后立即回读，首次成功不等待；失败/旧值最多三次读取、250ms 重试间隔、900ms 软调度预算。同步驱动调用可能超过预算，不能把此值当成黑屏上限。失败时最多只读刷新一次物理句柄，核对身份并释放句柄。
- 近期切屏写入成功但仅回读失败时，允许用户明确确认 AOC 外接屏当前桌面；需要先前已确认的映射，绑定操作、映射、会话代次，两分钟过期。新切屏、断线、显示器变更、紧急恢复等均撤销旧证据。没有发出写入、通用 worker 错误、超时、清理不确定均不提供该入口。
- 视觉确认不自动启用输入，选择来源且两端输入能力齐全后才启用；已接受的同一操作观察证据不再因来源选择而重复读取失效的 DDC 通道。Mac 输入桥额外检查 armed，缺省/false 均关闭输入。
- 两端显示键鼠未就绪原因；Mac 分项显示辅助功能、输入监听、事件钩子状态。录屏授权与键鼠授权拆开。
- 最近一次切屏命令及查找/预读/写入/回读阶段耗时显示在控制台；明确标注不是实际黑屏时长。

## 验证

- 最终 Python 回归共 46 项通过（含本机 TLS 互通与错误证书拒绝）。TLS 用例因沙箱不允许绑定临时端口，改为获准的本机回环测试后通过；未连接用户的 Windows。
- 新视觉确认回归先复现 3 项失败，再修复；5 项测试覆盖 16 种正常/权限/过期/错目标/错操作/断线/换显示器/重放/超时/worker 错误等场景。
- DDC 策略 11 项测试、12 个场景：一次写入、立即成功、瞬时失败恢复、旧值恢复、预算边界、调用阻塞、读句柄刷新与阶段时间。测试不操作真实显示器。
- 真实 Mac InputBridge.applyState 测试先复现 3 项失败，修复后 7 项检查通过；无事件钩子注册或输入注入。
- Mac 权限状态与画面确认纯逻辑测试通过。UI 核验模型所有动作隔离测试通过，未创建网络/原生服务。
- Mac arm64 / macOS 13 完整优化编译、临时签名验证通过；Windows C#5 / .NET Framework 4.8 x64 编译通过。
