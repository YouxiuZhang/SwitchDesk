# 双栖：切换输入时的只读观察

Windows 已成功读到一次显示器输入码 `17`。这次观察用来确认：你手动切到 Mac 后，Windows 还能否读到显示器，以及输入码会怎样变化。工具不会发送切屏指令，也不修改分辨率或刷新率。

## 操作一次即可

1. 完整解压观察包，保持四个文件在同一文件夹。两台电脑的视频线都保持连接，让 27G2 先显示 Windows。
2. 在该文件夹打开 PowerShell，执行：

```powershell
.\observe-input.ps1 -OutputPath .\input-observation.json
```

3. 观察默认持续约 **45 秒**：先保留 Windows 画面约 10 秒，再用**显示器上的按键/菜单**切到 Mac，确认能看到 Mac 桌面并保持约 10 秒，然后用显示器菜单切回 Windows，等待命令结束。不要关闭原来的 Windows PowerShell 窗口。
4. 把生成的 `input-observation.json` 提供给开发者，并说明中间是否确实看到 Mac 桌面。报告不会自动上传。

切换动作由你操作显示器完成；脚本只是后台读取。如果没有切到 Mac，照实说明，不把等待时间当作切换成功。

## 输出与异常

已有同名文件不会被覆盖，再运行时换一个文件名。每次查询都有超时，读取失败会记录在报告里，不会伪装成成功。如果无法确认超时子进程已经停止，观察会提前结束并保留 `cleanup_failed` 状态。

需要更长的手动操作时间时，可运行：

```powershell
.\observe-input.ps1 -DurationSeconds 90 -OutputPath .\input-observation-90s.json
```

如果脚本报错或执行策略阻止运行，保留报错信息反馈；不需要管理员权限，也不要修改全局执行策略或关闭防护。

## 这份报告说明什么

记录内容为采样时间、显示器枚举结果、输入码和查询错误。不记录屏幕画面、键鼠内容、剪贴板、网络地址或设备序列号。现有 `diagnose.ps1` 和 `Probe.cs` 随包提供，无需另外安装开发环境。

两个不同输入值只能说明回读发生变化；主机与输入码的对应还需结合你实际看到的画面。即使 Windows 在 Mac 画面期间仍可回读，也仍需下一步的软件写入和切回验证，不能直接判定自动切屏已完成。

这是开发验证工具。正式产品仍按后台检测设计，不增加独立检测页面。
